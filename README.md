# 🚆 경의중앙선은 왜 항상 기다리는가?

## 💡 분석 계기

경의중앙선으로 매일 통학하면서 배차 간격이 길고 지연이 잦아
불편함을 겪은 경험에서 출발했다. 단순한 불만에 그치지 않고,
실제 공공데이터로 "얼마나 많은 사람이 이 노선을 이용하는데
공급은 얼마나 부족한가"를 수치로 증명하고자 했다.

## 링크
- 대시보드: https://railway-2026.streamlit.app/
- GitHub: https://github.com/hjhee54-star/railway-analysis-2026

## 사용 프롬프트

```
너는 Python, SQLite, Streamlit에 능통한 시니어 개발자이면서, 코딩을 처음 배우는
사람에게도 쉽게 설명할 수 있는 특별한 재능을 가지고 있어.
공공데이터 분석 대시보드를 Streamlit으로 만들기 위한 코드(app.py, requirements.txt)를
작성해줘. 초보자도 그대로 실행할 수 있도록 과정을 자세히 설명해줘.

[분석 주제]
대주제: 경의중앙선은 왜 항상 기다리는가?
- 수요는 많고 공급은 부족한 광역철도의 배차 불균형을 분석하여,
  시간대별 혼잡 패턴과 노선 간 수송량 차이를 파악한다.

[데이터]
railway.db (SQLite)가 같은 폴더에 있고, 스키마는 다음과 같아.

시간대별승하차(id PK, 월, 노선명, 역명, 구분[승차/하차],
  t06, t07, t08, t09, t10, t11, t12, t13, t14, t15,
  t16, t17, t18, t19, t20, t21, t22, t23, t24, total)
노선별수송(id PK, 노선명, 구분[승차/하차],
  m01~m12[월별수송량], total)
경의중앙선역(id PK, 노선명, 역명)

[차트 3개 만들기]
각 차트마다 ① 시각화, ② 사용한 SQL, ③ 인사이트(2~3줄)를 함께 보여줘.

차트1. 시간대별 승하차 패턴 — 언제 가장 붐비는가? (막대 차트)
- 경의선+중앙선의 시간대별 승차/하차 인원 집계
- 출퇴근 피크(07~09시, 17~19시) 구간 강조 표시
- SQL 핵심:
  SELECT 구분, SUM(t06)~SUM(t24)
  FROM 시간대별승하차
  WHERE 노선명 IN ('경의선','중앙선') AND 월=3
  GROUP BY 구분

차트2. 노선별 수송량 비교 — 경의중앙선의 위치는? (가로 막대 차트)
- 전체 광역철도 노선별 1분기 승차 인원 비교
- 경의선·중앙선을 빨간색으로 하이라이트
- SQL 핵심:
  SELECT 노선명,
    COALESCE(m01,0)+COALESCE(m02,0)+COALESCE(m03,0) AS 1분기합계
  FROM 노선별수송
  WHERE 구분='승차' AND m03 IS NOT NULL
  ORDER BY 1분기합계 DESC

차트3. 역별 이용량 랭킹 — 어느 역이 가장 붐비는가? (가로 막대 차트)
- 경의중앙선 역별 총 승차 인원 및 피크 집중도 산출
- 피크 집중도 = 출퇴근 6시간 / 전체 이용량 * 100
- SQL 핵심:
  SELECT 역명, SUM(total) AS 총이용객,
    ROUND((SUM(t07)+SUM(t08)+SUM(t09)+SUM(t17)+SUM(t18)+SUM(t19))
    *100.0/NULLIF(SUM(total),0),1) AS 피크집중도
  FROM 시간대별승하차
  WHERE 노선명 IN ('경의선','중앙선') AND 구분='승차'
  GROUP BY 역명 ORDER BY 총이용객 DESC

[요청사항]
- railway.db가 없으면 친절한 한국어 에러 메시지 출력 후 st.stop()
- 사이드바에 월 선택(1~3월) 및 노선 구간 선택 필터 추가
- 각 차트 아래에 사용한 SQL과 인사이트 함께 표시
- 상단에 KPI 카드 4개 (역 수, 총 승차, 아침 피크, 저녁 피크)
- @st.cache_data로 쿼리 결과 캐싱
- st.set_page_config(layout="wide") 사용
- requirements.txt에는 streamlit, pandas, plotly, openpyxl 포함
```

## 데이터 및 클렌징 과정

**원천 데이터**: 코레일 공공데이터포털 (2026년 1~3월)
- `(2026년3월) 광역철도 시간대별 승하차인원(홈페이지).xlsx`
- `(2026년3월) 광역철도 수송(홈페이지).xlsx`

**클렌징 과정**
1. xlsx 파일 상단 7행 메타데이터(검색조건 등) 제거 후 데이터 파싱
2. 시간대 컬럼명 한글 → 영문 변환 (SQLite 호환: t06, t07 ... t24)
3. 월별 수송량 컬럼명 변환 (m01~m12)
4. 노선 소계 행(역명 없는 행) 제거
5. SQLite DB(railway.db) 3개 테이블로 저장
   - 시간대별승하차 (1,852행)
   - 노선별수송 (682행)
   - 경의중앙선역 (47개역)

## 시각화 결과 및 인사이트

**차트① 시간대별 승하차 패턴**
경의중앙선의 최대 승차 피크는 07~08시 출근 시간대로, 출퇴근 6시간에
이용량이 집중되는 전형적인 통근 노선 패턴이 나타난다.
이 시간대 배차 간격이 길어질수록 혼잡도와 지연의 악순환이 발생한다.

**차트② 노선별 수송량 비교**
경의선은 전체 광역철도 중 중위권 수송량을 보이며,
경부선·분당선 대비 수송량은 적지만 통근 수요는 결코 낮지 않다.
수요 대비 배차 공급이 부족한 구조적 문제가 존재한다.

**차트③ 역별 이용량 랭킹**
일산, 도농, 행신 등 외곽 거점역에서 이용량이 집중되며,
피크 집중도가 높은 역일수록 출퇴근 시간대 혼잡이 심각하다.
이런 역을 중심으로 출퇴근 시간대 증편이 우선적으로 필요하다.
